# Delivery roadmap

The complete product is not finished by the deployed foundation PR.

1. **Current PR:** authoritative contracts/assignments, signed intake, immutable history,
   outbox/workflows, baseline source checks, optional AI, judge evidence UI and passing
   CI/native automatic Cloudflare PR Preview.
2. **Genuine staging loop:** App installation, approved
   challenges/teams, real PR → workflow → Check → judge view; running Checks and publication recovery.
3. **Functional checks:** Node microVM adapter and trusted HTTP test policy implemented
   with deployment disabled by owner request. Next: actual image/VM/adversarial validation,
   enabled baseline/head execution, more runtimes, full builds/security/coverage/benchmarks
   and R2 artifacts.
4. **Judge operations:** individual identities, roles, human adjudication, richer challenge authoring, pagination/filters and retention.
5. **Event hardening:** deadline load/failure drills, metrics/alerts, backup/recovery,
   baseline caching, stronger secret scans and stale-job cancellation.
6. **Evidence-driven expansion:** benchmarks, coverage, symbols/public API analysis, reusable
   indexes, verified additional work, specialized reviews and cost routing.

Every slice uses a coherent PR and Cloudflare review. The owner decides merges.

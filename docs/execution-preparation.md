# Offline dependency preparation and execution observations

The organizer can opt into `dependencies: {mode: "NPM_OFFLINE_V1", npmVersion: "11.19.0", lockHash: "<SHA-256 of package-lock.json bytes>"}` in the frozen runner policy. Both baseline and head must satisfy that frozen lock identity. This profile supports npm lockfile v3, registry tarballs with SHA-512 integrity, and an exact matching `packageManager` in package.json. Local links, Git packages and alternate registries are rejected.

The immutable image contains a catalogue populated by its pinned runner/package-lock.json. npm ci runs offline inside each fresh bounded guest, using a private copy of that catalogue; lifecycle scripts and participant .npmrc are disabled. No participant install runs on the host or receives network access. Catalogue misses are install FAIL; checks that could depend on the missing installation remain UNVERIFIED. Unsupported or mismatched inputs never produce PASS. Add required packages to the organizer image catalogue before freezing a new image and policy.

`dependency-preparation` records the first actual installation's exit code, duration, bounded redacted output, npm version, lock hash and image identity. The local adapter runs at most two supplemental checks concurrently in separate clean guests. The Cloudflare adapter remains sequential because its API provides one guest per runner instance. Changed-path review planning can focus documentation, security or source review but never removes frozen checks. Documentation profiles without configured benchmarks run none; configured benchmarks remain required regardless of changed paths.

Reusable setup is the immutable image's package catalogue, never participant-written node_modules or a writable shared cache. Every acceptance service and supplemental check starts clean and performs its own install. Every benchmark obtains fresh warmup and validated samples; historical benchmark results cannot enter the execution result cache.

Optional result metrics record first-guest startup through source initialization, excluding dependency installation and application readiness, and exact Node/npm versions obtained from trusted prepared tools. Local Docker resource samples read kernel-owned cgroup v2 counters after service/command checks. CPU is cumulative microseconds for that guest; memory and PIDs are observations at the sample time. Values include setup and probe overhead. They are neither peak usage nor configured capacity. Each sample's scope and timestamp are validated. Unavailable observations remain absent. Cloudflare resource consumption, disk usage and provider cost are currently unavailable.

Run `docker build --tag judge-c2c-runner-dependencies runner` and `node scripts/dependency-docker-rehearsal.mjs` for the synthetic local rehearsal. It validates offline installation, hostile lifecycle/config suppression, repeated immutable setup with fresh benchmarks, cache-miss failure, lock rejection, preserved dependent uncertainty and guest cleanup. Evidence is in `docs/qa/dependency-docker-evidence.json`; it does not attest a live hackathon or deployed Cloudflare execution.

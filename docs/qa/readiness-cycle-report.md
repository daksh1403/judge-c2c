## Evaluation quality

Objective criteria control functional statuses. CallMissed output is locally validated against known requirements and evidence IDs; missing or invalid reasoning does not erase execution. [Calibration evidence](payment-calibration-evidence.json) preserves the actual reports and statuses. Source-security patterns record locations/counts as UNVERIFIED potential risks, never exploitability. Opt-in npm OSV comparison supports exact declared versions in lockfile v2/v3; ranges, aliases, workspace links and manifest/lock inconsistencies remain UNVERIFIED. It does not prove installed package integrity.

Trusted HTTP latency checks validate response behavior before measuring, retain samples/p95/warmup/budget and compare both commits through the existing execution evidence model. Measurements include evaluator transport overhead and are environment-specific, not production throughput claims. The real Docker benchmark fixture completed ten validated samples; no latency credit is awarded for fast wrong responses.

The first actual partial/manipulated CallMissed attempts both failed local semantic validation. Their completed evaluations retain objective failures and expose AI failure instead of fabricated analysis. Policy v5 adds static validation repair feedback and failure categories; retries create new historical attempts. Successful calibration is still pending until those real retries complete.

## Security / adversarial results

Controlled guests could not access external networking, metadata endpoints, host root writes, evaluator secrets or another submission. CPU loops and oversized output terminate without destroying independent successful evidence. Process creation is bounded. Prompt injection remains repository data; protected tests remain authoritative policy. These are bounded development-VM probes, not a proof against all kernel escapes or event-scale adversaries.

## Fairness risks

Assignments preserve the contract version existing when assigned. Unknown/conflicting mapping requires explicit resolution. Successful repository CI and closed GitHub issues do not prove challenge completion. Judge console credentials are read-only shared role codes; per-person judge identity and finer event/team authorization are not yet implemented. Extra App installation write permissions remain an owner-admin least-privilege cleanup; minted evaluation tokens are explicitly downscoped.

## Performance

Recovery processes bounded outbox/publication batches and prioritizes recent queued heads. Benchmarks are configurable and bounded. Current development runner capacity is intentionally small; twelve fixture actors are not a production load test. Prepared dependency caches, warm multi-host execution and comprehensive queue/cost telemetry remain incomplete.

## Launch blockers

1. Production-grade isolated execution capacity, capacity planning and hostile-code recovery drills. Development Docker/tunnel remains development-only.
2. Production state/auth provisioning and approved merges. No PR has been merged by this agent.
3. Cloudflare R2 is disabled (provider error 10042); large object artifact retention remains blocked. Bounded database evidence downloads are available, with a 2 MB limit and integrity digest.
4. Full acceptance-ledger audit: unverified/missing features are not waived, including participant scopes, per-person console identity, full scans/coverage adapters, additional-contribution verification and broader moderation.
5. Wider model calibration, real multi-account integration and event-scale bursts. Current calibration demonstrates three controlled code personas, not statistical judging accuracy.
